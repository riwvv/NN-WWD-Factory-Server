# NN-WWD-Factory-Server

Серверная часть для фабрики по обучению кастомных моделей детекции ключевых слов (Wake Word Detection). Работает в связке с [клиентским приложением](https://github.com/riwvv/NN-WWD-Factory).

## 📦 Возможности

- Генерация синтетического датасета через TTS (Silero) — positive (ключевое слово), плюс три вида negative: случайные слова, орфографически похожие слова, шум
- Подмешивание реальных записей пользователя (`real_samples/positive`, `real_samples/negative`) с аугментацией, чтобы модель не переобучалась только на синтетике
- Извлечение эмбеддингов через заморожённый бэкенд [openWakeWord](https://github.com/dscripka/openWakeWord) (mel-спектрограмма → Google `speech_embedding`) вместо обучения CNN с нуля — бэкенд уже предобучен на огромном объёме речи, наша голова учится только различать конкретное слово
- Time-shift аугментация и групповой train/val split (аугментированные копии одной записи не разъезжаются между train и val — иначе `val_acc` завышается)
- Честная оценка на отложенном held-out наборе (`test_samples/`, `evaluate_model.py`) — отдельно от `real_samples/`, который участвует в обучении
- Управление задачами (статус, прогресс)

## 🧠 Архитектура пайплайна

```
waveform (1с, 16кГц)
   │
   ▼
melspectrogram.onnx  ─┐
   │                  │  заморожённый бэкенд openWakeWord,
   ▼                  │  предобучен на большом объёме речи,
embedding_model.onnx ─┘  не переобучается
   │
   ▼  (скользящие окна 76 фреймов, шаг 8 → 3×96 эмбеддинга)
{wake_word}_model.onnx   ← это единственное, что обучается
   │                        (лёгкая голова: Linear→ReLU→Dropout→Linear,
   ▼                        нормализация запечена прямо в граф)
probabilities [not_wake_word, wake_word]
```

Раньше вместо этого обучалась CNN с нуля прямо на mel-спектрограмме — работало плохо: пары тысяч клипов недостаточно, чтобы одновременно выучить и акустику речи вообще, и конкретное слово. Модель переобучалась на отпечаток сессии записи (комната/микрофон), а не на само слово.

## 🚀 Быстрый старт

### 1. Создай и активируй виртуальное окружение

```bash
python -m venv .venv
.venv\Scripts\activate   # Windows
# source .venv/bin/activate   # Linux/macOS
```

### 2. Установи зависимости

```
pip install -r requirements.txt
```

### 3. Запусти сервер

```
python main.py
```
Сервер запустится на http://127.0.0.1:8000. Документация доступна по адресу: http://127.0.0.1:8000/docs.

### 4. (опционально) Подмешай свои записи

Положи `.wav` в `PythonServer/real_samples/positive/` (реально сказанное ключевое слово) и `PythonServer/real_samples/negative/` (что угодно ещё) — они автоматически подмешаются в датасет со следующим запуском обучения.

### 5. (опционально) Оцени модель на held-out наборе

```
python evaluate_model.py --model путь/к/{wake_word}_model.onnx --config путь/к/config.json
```
Файлы для оценки кладутся в `PythonServer/test_samples/positive` и `.../negative` — этот набор никогда не попадает в обучение, поэтому цифры оттуда что-то значат.

## 🔧 Основные эндпоинты

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/train-full-pipeline` | Запуск полного пайплайна: генерация датасета + обучение |
| `GET` | `/generate-status/{task_id}` | Статус задачи |
| `GET` | `/download/{task_id}` | Скачать сырой файл/архив задачи |
| `GET` | `/download-package/{task_id}` | Скачать ZIP с готовым пакетом модели |
| `POST` | `/shutdown` | Остановить сервер (без аутентификации — не выставлять наружу без защиты) |

`/download-package` отдаёт архив с четырьмя файлами: `melspectrogram.onnx`, `embedding_model.onnx` (заморожённый бэкенд, одинаковый для любого ключевого слова), `{wake_word}_model.onnx` (обученная голова) и `config.json` (структурные параметры пайплайна: размер окна, шаг, размерность эмбеддинга — нужны потребителю, чтобы правильно прогнать цепочку из трёх моделей).

## 📂 Структура

```
PythonServer/
├── app/
│ ├── api/        # Эндпоинты
│ ├── core/       # Конфигурация (в т.ч. REAL_SAMPLES_DIR)
│ ├── models/     # Схемы данных
│ ├── services/   # Генерация датасета, эмбеддинги, обучение, пайплайн
│ └── utils/      # Текстовые/файловые утилиты
├── real_samples/       # (не в git) сюда кладутся реальные записи для обучения
├── test_samples/       # (не в git) held-out набор для evaluate_model.py
├── evaluate_model.py   # честная оценка на held-out наборе
├── main.py             # точка входа
└── requirements.txt
```
